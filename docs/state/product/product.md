# Что это

AI Access Proxy Layer — гейт гранулярных прав для AI-агентов. Владелец один раз подключает внешние сервисы (Google, Meta, LinkedIn, Stripe, Notion, Jira, Slack — всего 27) по OAuth, а агенту выдаёт MCP-эндпоинт с ключом `sg_…`, у которого разрешён только явно отмеченный набор действий.

## Кому

Тем, кто пускает AI-агента в **чужие** аккаунты — агентствам и командам, у которых аудит доступа записан в договоре с клиентом. Агент получает не токен, а узкий проброс через прокси. Соло-разработчику со своим собственным токеном эта боль не болит — это не ICP.

Позиционирование — least-privilege, а не каталог интеграций: в гонке за количеством коннекторов (Composio, Pipedream, Zapier MCP — 2000+) выиграть нельзя, и 27 провайдеров заявляются как достаточное покрытие, а не как аргумент.

## Что даёт

- **Гранулярность** — право выдаётся на действие, не на сервис.
- **Отзыв в один клик** — перевыпуск ключа эндпоинта не трогает подключение сервиса.
- **Аудит** — каждый вызов инструмента пишется в `AuditLog` (кто, чем, с каким исходом).
- **Токены не покидают систему** — шифруются AES-256-GCM, обновляются сами, при мёртвом токене приходит уведомление «Reconnect required».

## Состояние

Два деплоя из одной кодовой базы, переключаются `SCOPEGATE_CLOUD`:

- **Облако** (`scopegate.dev`) — лендинг, `/pricing`, биллинг на Polar, планы из `src/lib/plans.ts`, вход через Google или magic link.
- **Self-host** — те же фичи без биллинга, `docker compose --profile local up`, вход по инвайту.

Публичная регистрация паролем выключена в обоих режимах (`disableSignUp: true`).
