# Web Vitals — 2026-07-28

**Target:** https://scopegate.dev  ·  **Strategy:** mobile  ·  **Source:** lab (local Lighthouse, native arm64)

## Investigation of Task #198 (LCP 24.6s / TBT 93.1s on 2026-07-27)

Root-cause read of the actual render path found no code defect:

- `/` (`src/app/page.tsx`) is a 4-line server component that immediately `redirect()`s
  to `/login` (anon) or `/projects` (auth) — no client JS runs on `/` itself.
- `/login` (the page an anonymous Lighthouse crawl actually renders) is a trivial
  client component: `useState` for form fields, one `handleSubmit` fired only on
  submit. No `useEffect`, no polling, no `setInterval`, no heavy libraries.
- No analytics/OTel-browser script, no background polling reachable pre-auth.

The 2026-07-27 run was taken on this machine's default shell Node, which is an
**x86_64 binary running under Rosetta translation** on this Apple Silicon (M3 Pro)
host (`uname -m` reports `x86_64` even though the hardware is arm64) — a known
false-positive generator for Lighthouse CPU-bound metrics (TBT/LCP) on this machine.

Re-ran Lighthouse via a native arm64 Node (`~/.nvm/versions/node/v22.15.1/bin/node`,
`arch -arm64`) twice against the same live URL:

| Run | LCP | TBT | CLS | TTFB | FCP | Score | Warning |
|---|---|---|---|---|---|---|---|
| native #1 | 4.17s | 110ms | 0.07 | 36ms | 1.81s | 81 | none |
| native #2 | 6.77s | 4.90s | 0.07 | 36ms | 4.40s | 33 | "slower CPU than expected" |

Both runs hit the same production build; only the local machine's load differed
(`load average` was 15.55 at the time of run #2 — dozens of background dev-agent
processes on this box). **TTFB stayed flat at 36ms in both runs** — proof the
server itself responds fast regardless of local load; the swing is entirely in
client-side/CPU-bound metrics (LCP/TBT/FCP), which is exactly what a contended
local Lighthouse host produces, not a real product regression.

## Conclusion

No code change made — there is nothing to fix in the current source. The
2026-07-27 "poor" numbers are a local-machine measurement artifact (Rosetta
translation + host contention), not a genuine performance regression.

## Recommendation

Run `/darkflow:web-vitals` from an idle/dedicated machine or a CI runner instead
of this shared dev box, and take the median of ≥2 native-arch runs before filing
a task. Cross-check against real-user field data (CrUX / PageSpeed Insights) when
in doubt about a local lab result.
