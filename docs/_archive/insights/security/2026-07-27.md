## Recurring Issues

- **SSRF — 4-й аудит подряд** (2026-06-07 #88 → 2026-06-21 #144 → 2026-07-19 #187 → сегодня). Прежние итерации чинили `safeFetch` изнутри; сегодняшняя находка — первый путь, который эту защиту **обходит целиком** (IMAP/SMTP-сокет вместо HTTPS). Вывод: точечное укрепление `safeFetch` не масштабируется, нужен один общий guard «проверь хост перед исходящим соединением» для всех сетевых стеков.
- **Валидация внешне управляемых строк перед отправкой наружу — 2-й аудит подряд** (2026-07-14 #161: CRLF-инъекция в заголовки письма → сегодня: инъекция в URL-путь). Тот же класс: параметр инструмента дописывается в текстовый протокол без экранирования.

## Hypotheses

- H-014 — «SSRF-находки перестанут повторяться только после общего guard'а на все исходящие соединения (а не только `safeFetch`)»: evidence — 4 подряд аудита с SSRF-находкой, из них последняя вне HTTPS-стека. Статус: открыта, проверяется после закрытия задачи #190.

## Recommendations

1. **Path traversal в MCP-инструментах** (задача #188, high) → кодировать каждый подставляемый сегмент через `encodeURIComponent` в `createFetchTool` и в ручных хендлерах + добавить в `service-fetch.ts` проверку, что нормализованный URL остаётся внутри `baseUrl` провайдера. Критерий приёмки: `notion_get_page` с `page_id="../users"` не порождает запрос на `https://api.notion.com/v1/users`, есть unit-тест.
2. **Дефолты секретов в compose** (задача #189, high) → заменить `${VAR:-default}` на `${VAR:?required}`, удалить мёртвые build-args, добавить fail-fast на дефолтный/короткий `BETTER_AUTH_SECRET`. Критерий приёмки: `docker compose config` без переменной падает с ошибкой.
3. **SSRF через imapHost/smtpHost** (задача #190, medium) → экспортировать `isPrivateIp`/`resolveAllAndValidate` из `safe-fetch.ts` и применять их к почтовым хостам, ограничить порты аллоулистом, не возвращать сырой текст ошибки. Критерий приёмки: `imapHost=127.0.0.1` отклоняется до открытия сокета, есть unit-тест.
4. **Low, задачи не заводились** → при появлении доверенного прокси зафиксировать его в `getClientIp()` (брать не первый, а последний непроверенный hop); перевести сравнение `CRON_SECRET` на `timingSafeEqual`.
