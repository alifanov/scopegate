# Build Optimization — 2026-07-27

**Scope:** `.github/workflows/darkflow-ci-gate.yml` (+ фактические прогоны через `gh run list` / `gh api .../actions/runners`), `Dockerfile`, `Dockerfile.cron`, `docker-entrypoint.sh`, `docker-compose.yaml`, `docker/crontab`, `docker/prisma.config.ts`, `.dockerignore`, `next.config.ts`, `package.json` scripts, `tsconfig.json`, `vitest.config.ts`, git churn (последние 30 коммитов).

## Pipeline overview

`git push master` → **(1) CI-gate** (`darkflow-ci-gate.yml`): `pnpm install --frozen-lockfile` → **build** (`prisma generate && tsc --noEmit`, DB-less) → `lint` → `test`; красный → issue `source:ci`. Параллельно → **(2) Coolify**: clone → multi-stage `docker build` (`node:22-slim`): **deps** (манифесты + prisma → `pnpm install` с BuildKit pnpm-store mount) → **builder** (`COPY . .` → `prisma generate && next build` с BuildKit `.next/cache` mount, standalone) → **runner** (`.next/standalone` + static + public + prisma + отдельный `npm install prisma` в `/prisma-runtime`, non-root `node`) → старт: `prisma migrate deploy` → `node server.js`. Плюс отдельный сервис `cron` (`Dockerfile.cron`, alpine + supercronic) — новое с прошлого аудита.

Docker-часть пайплайна остаётся в оптимизированном состоянии (7-й раунд). **Регрессия в CI-части**: гейт физически не выполняется с ~20 июля — self-hosted runner offline, прогоны висят 24 ч и отменяются.

## Recommendations

1. `.github/workflows/darkflow-ci-gate.yml` → заменить `runs-on: [self-hosted, Linux, X64]` на `ubuntu-latest`, добавить `pnpm/action-setup@v4` (10.9.0) + `actions/setup-node@v4` (node 22, `cache: pnpm`). **Критерий:** push в `master` даёт завершённый прогон за ≤ 5 мин, `gh run list` показывает `success`/`failure`, а не `cancelled`. (#197)
2. Там же → `timeout-minutes: 15` на job `gate`. **Критерий:** зависший прогон падает как `failure` и заводит issue `source:ci`, а не молча отменяется через сутки. (#197)

## Notes (minor / not filed)

- **`concurrency` не задан**: воркер `fix-issues` пушит каждые 15 мин, прогоны на устаревших коммитах не отменяются и копятся (сейчас это и вылилось в очередь из 7 висящих job). `concurrency: {group: ci-${{ github.ref }}, cancel-in-progress: true}` — дешёвая гигиена, но экономия маргинальна. Заметка.
- **`cron`-сервис в `docker-compose.yaml` собирается с `context: .`** (~5 МБ контекста после `.dockerignore`) ради образа, который копирует только `docker/crontab`. Меньше секунды, только локальный `docker compose build`. Заметка.
- **`docker-compose.yaml` передаёт build args** (`BETTER_AUTH_SECRET`, `ADMIN_*`), а в `Dockerfile` нет ни одной `ARG` — молча игнорируются. Мёртвая конфигурация; секретная часть уже покрыта задачей безопасности #189. 7-й раунд заметкой.
- **Дубликат Prisma CLI в runner (~25–40 MB)**: архитектурно необходим (БД недоступна на этапе build, standalone-бандл не содержит CLI), слой закэширован. 7-й раунд заметкой.
- **CI build-шаг — `tsc --noEmit`, не `next build`**: не ловит next-специфичные ошибки (RSC-границы, роуты) — осознанный DB-less компромисс. Заметка.
- **CI: install → build → lint → test последовательны** в одном job; распараллеливание `lint`+`test` даст ~30–60 с, но требует переписывания хелпера `run_check`. Маргинально.
- **base image `node:22-slim`** (не alpine) — осознанный выбор ради явного `openssl` для Prisma. Заметка.
