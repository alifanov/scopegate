## 5 Recommendations

### 1. Реализовать 48h activation drip email — Priority: **High**

- **Metric**: 8 из 9 зарегистрировавшихся не вернулись. 0 `project_created`, 0 `service_connection`. Нет автоматического механизма re-engagement.
- **Action**: Создать API endpoint `/api/cron/activation-drip` + launchd plist (ежедневный запуск). Логика: найти пользователей, создавших проект 48–72 часа назад без ServiceConnection — отправить через Resend:
  - Тема: "Застряли на подключении сервиса? Вот как за 2 минуты..."
  - Ссылка на документацию + CTA "Подключить Google Calendar"
- **Impact**: Автоматический return rate 15-25% для всех будущих пользователей. Особенно критично сейчас пока база мала — каждый пользователь на счету.

### 2. Написать logicswarm.com лично — Priority: **Critical**

- **Metric**: Единственный органический пользователь, создавший реальный проект (`Atlant1s`, 2026-03-19). Не вернулся уже >48 часов. 0 ServiceConnections.

  - CTA: reply / Calendly link
- **Impact**: Прямой фидбек о блокере на ServiceConnection. Возможный первый activated user.
- **Рекомендуется сделать вручную** — это личное письмо.

### 3. Починить PostHog person identity merge — Priority: **Medium**

- **Metric**: Когортная воронка показывает 0 signups при реальных 9 регистрациях. PostHog не может связать анонимный `$pageview` (anonymous_id) с `user_registered` (userId) — это разные "persons" в PostHog.
- **Action**: В auth hook после `user_registered` также отправлять PostHog `$identify` event с `anon_distinct_id` → `userId` mapping. Для этого нужно передавать PostHog anonymous ID с клиента на сервер при signup (через hidden form field или cookie). Альтернатива: передавать `$anon_distinct_id` в `captureServerEvent` при регистрации.
  ```typescript
  // В signup form/page: передать posthog.get_distinct_id() на сервер
  // В captureServerEvent: добавить $anon_distinct_id свойство
  ```
- **Impact**: Восстановит точность когортных воронок, ретеншн анализа, attribution в PostHog. Без этого analytics funnel необратимо сломан.
