### Findings

- **Uncaught exception в проде**: `TypeError: Response constructor: Invalid response status code 204`, минимум 2 повторения за 24ч. Источник — `withSseKeepAlive()` (`src/app/api/mcp/[apiKey]/route.ts:24`): проверяет только `!response.body`, но не null-body статусы (204/205/304); при 204-ответе транспорта MCP с непустым стримом и `content-type: text/event-stream` конструктор `Response` кидает исключение. → задача #224 (`approved`, инцидент).
- `mcp.tool searchConsole_submit_sitemap` p99 30026.9мс — упирается в жёсткий лимит тула (30с), лог `Tool execution timed out after 30s`. У `searchConsole`-транспорта нет `timeoutMs` кроме явного для `/urlInspection/` путей — sitemap/site-операции висят без таймаута. → задача #225.
- `PUT` (безымянный спан) p99 237734.1мс — бинарная загрузка LinkedIn (`linkedinUploadImage`/`linkedinUploadDocument`, `src/lib/mcp/linkedin.ts:130,183`) через `safeFetch` без `timeout`. → задача #226.
- `/api/mcp/[apiKey]` 400×262 (0.48% трафика) — третий прогон подряд с повышенным уровнем (0.11% → 0.74% → 0.48%), H-002 теперь 3/3. → задача #227 (классификация `body_preview` сэмплов).
- `mcp.tool searchConsole_inspect_url` p99 5192.0мс / `service-fetch searchConsole` p99 5028.6мс — H-001 3/3, закрыта как confirmed/external: таймаут уже намеренно поднят до 30с в коде (комментарий про инцидент с 5с), фикса не требует.
- Google Ads: `Google Ads query error (400)` ×2 в логах — то же revoked-соединение (`cmmxnepr200f90kpiy9hx5kxq`), что вчера; уведомление уже отправлено, ручной реконнект на стороне владельца проекта, не задача агента.
