# Deckbook ScopeGate — карта и правила

## Дерево

```
logs/YYYY-MM-DD        дневной лог, секции по источникам — только дописывается
state/                 «как есть сейчас», перезаписывается
  arch                 карта системы (mermaid) + таблица решений D-NNNN
  spec/
    data-model         модели Prisma и связи
    screens            инвентарь экранов
    flows/             ключевые пользовательские потоки
  product/
    product            паспорт продукта (шапка) + что это
    glossary           доменные термины
  design/
    components         реестр UI-компонентов и паттернов состояний
_archive/              отработавшее; для контекста не читается
```

Отсутствующего документа нет — значит про это ещё нечего писать. Пробел ≠ дрейф.

## Что читать перед задачей

| Задача | Читать |
|---|---|
| UI / UX | `state/design/components`, `state/spec/screens` |
| Меняется пользовательский поток | `state/spec/flows/*` |
| Архитектура, новый сервис | `state/arch` (таблица решений — до предложения нового) |
| Данные, миграция | `state/spec/data-model` |
| Продуктовое решение | `state/product/product` |

## Что писать после

| Сделал | Обнови |
|---|---|
| Изменил поток | `state/spec/flows/*` |
| Добавил/убрал экран | `state/spec/screens` |
| Изменил модель данных | `state/spec/data-model` |
| Новый сервис, интеграция, смена стека | `state/arch` + строка в таблице решений |
| Новый UI-компонент или паттерн состояния | `state/design/components` |
| Любая проверка-рутина | секция в `logs/YYYY-MM-DD` |

`write_document` перезаписывает документ целиком — сначала прочитай, потом пиши.

## Формат задач

- **Заголовок** — симптом, не диагноз: «MCP-эндпоинт отдаёт 500 при истёкшем токене Meta», не «поправить обработку ошибок».
- **Описание** — три блока: симптом с цифрами · где смотреть (файл:строка, ссылка на `logs/YYYY-MM-DD`) · критерии приёмки (проверяемые).
- **Приоритет** — `high` только для сломанного в проде или утечки данных.
- Без пересказа того, что уже есть в логе или коде.

## Инцидент или предложение

- **Инцидент** — сломано сейчас (сайт лежит, 5xx, деплой красный, уязвимость): задача остаётся в `todo`, чинится без спроса.
- **Предложение** — улучшение, рефакторинг, оптимизация: сразу после `create_task` перевести в `needs_human`. Решает владелец; молчание согласием не считается.

## Порог «наблюдение → задача»

Задачу заводить, когда наблюдение подтверждено:
- 3+ дневных лога подряд с одним и тем же симптомом, **или**
- 2+ независимых источника (например SigNoz + Lighthouse).

Разовый выброс — строка в логе, не задача. Исключение: инцидент — сразу задача.

## Лаконичность

- Комментарий к задаче — 1–3 предложения.
- Документы — тезисы, цифры, таблицы; не проза.
- Без вводных, без «в целом всё ок», без пересказа кода.

## Ретеншен

`logs/` старше 4 недель → `_archive/logs/` (рутина `scopegate-rotate-logs`, 1-го числа).
