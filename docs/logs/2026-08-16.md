### Findings

- **Uncaught exception в проде (recurring)**: `TypeError: Response constructor: Invalid response status code 204` в `scopegate-selfhost`, тот же текст, что и в задаче #224 (фикс `withSseKeepAlive` от 2026-08-13, commit 3e93f97) — но фикс закрыл только SSE-обёртку в `route.ts`. Реальный источник — общий транспорт `makeRequest()` в `src/lib/mcp/safe-fetch.ts:227`: всегда строит `new Response(stream, {status})` без проверки на null-body статусы (204/205/304), которым Fetch-спека запрещает body. Бросок происходит синхронно в callback `https.request`, минуя `reject()` — неперехваченное исключение уровня процесса, затрагивает общий транспорт всех 26 провайдеров. → задача #254 (`critical`, incident — заведена сразу, без наблюдательного порога).
- `GET /login` p99 581мс на `scopegate-cloud` — чуть выше порога "медленно" (500мс), но DB-запросы в этом окне все ≤10мс и повторяемости в предыдущих снапшотах нет → ниже порога для задачи, отслеживается только здесь.
- Рост трафика `scopegate-cloud` за 7д (39110 из 68239 — за последние 24ч) — не аномалия: 7-дневное среднее занижено обрывом телеметрии 2026-08-13→14 (см. `docs/logs/2026-08-14.md`, задача #231), сравнение с этим окном некорректно. Дневной объём (39110/55317) в норме относительно 2026-08-12/13 (78375/54331).
- `/api/mcp/[apiKey]` 400×172 на `scopegate-selfhost` — тот же паттерн, что закрыт как non-defect (H-002, см. раздел Changes выше).
