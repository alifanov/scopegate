# Поток: приглашение и вход

Публичная регистрация по паролю выключена в **обоих** режимах (`disableSignUp: true`): `POST /api/auth/sign-up/email` всегда возвращает ошибку. Это закрывает только один конкретный путь — сам better-auth `signUpEmail`; ниже показаны все пути, которыми пользователь реально попадает в систему.

## Self-hosted — только инвайт

1. Админ (`ADMIN_EMAIL`) создаёт инвайт на `/admin/users` → `POST /api/admin/invites` → `InviteToken`.
2. Приглашённый открывает `/invite/[token]`, задаёт пароль.
3. `POST /api/auth/accept-invite` создаёт `User` + `Account` **прямыми вызовами Prisma** (через better-auth нельзя — путь закрыт `disableSignUp`), пароль хэшируется `ctx.password.hash()`, `emailVerified: true`.
4. Пользователь добавляется в проект как `TeamMember`, дальше входит через `/login`.

Первый админ поднимается на старте приложения из `ADMIN_EMAIL` / `ADMIN_PASSWORD` (`bootstrap.ts`).

## Cloud — инвайт + самостоятельная регистрация

В облаке (`SCOPEGATE_CLOUD=1`) `/signup` открыт (в self-host рендерит `notFound()`) и добавляет два пути, которые создают пользователя в обход `signUpEmail`/`disableSignUp` — каждый по своей собственной логике:

- **Google** (`socialProviders.google`) — отдельный OAuth-клиент `GOOGLE_SIGNIN_CLIENT_ID`/`SECRET`, не тот, что у сервисных подключений (`GOOGLE_CLIENT_ID`). Отдельный клиент под логин избавляет его от CASA-ревью, которое тянет за собой `gmail.modify`/`drive`.
- **Magic link** (плагин `magicLink`, только когда `isEmailConfigured()`) — письмо со ссылкой; сессия открывается без пароля.

Инвайт-путь остаётся доступным и в облаке — так в существующий облачный проект добавляют тиммейта без Google/почты.

### Magic link ведёт не туда, куда кажется

`sendMagicLink` строит ссылку через `magicLinkUrl()` на `/magic-link?token=…`, а не на встроенный `/api/auth/magic-link/verify`. Причина: почтовые сканеры безопасности сами открывают ссылки из письма GET-запросом ещё до пользователя — если бы ссылка вела прямо на verify-эндпоинт, одноразовый токен сгорал бы раньше клика. `/magic-link` — собственная страница (`magic-link-client.tsx`), она делает редирект на настоящий verify только из `useEffect` в браузере, то есть только по реальному клику пользователя.

## Проверка

Регистрация без токена/Google/magic-link невозможна; использованный invite-токен и использованная magic-link-ссылка повторно не срабатывают; после входа любым из путей пользователь видит только свои проекты; `/signup` в self-host отдаёт 404.
